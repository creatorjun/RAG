# ADR-0008: 실행 중 품질 규칙을 비차단 관찰 지표로 전환

## 상태

Accepted — 2026-08-17

## 배경

Task 본문이 필수 문구·섹션·Claim·Evidence coverage 규칙을 완전히 만족하지 않으면 같은 생성을
반복한 뒤 Job을 `NEEDS_ATTENTION`으로 멈추는 구조였다. 로컬 모델의 표현 차이도 실패로 분류되어
긴 Job이 자주 중단됐고, 규칙에 맞춘 재작성은 실제 문서 품질을 안정적으로 높이지 못했다.

## 결정

- 본문 문구, 필수 섹션, 완료 마커, 인용 유무, Claim/Evidence coverage는 실행 합격 조건으로 쓰지 않는다.
- 생성된 비어 있지 않은 결과는 저장하고 조립·게시까지 진행한다.
- 기존 Task·최종 validation 파일 형식은 체크포인트 호환성을 위해 유지하되 새 보고서는 항상
  비차단 상태이며 coverage 건수는 관찰 지표로만 기록한다.
- 과거 품질 규칙 때문에 `NEEDS_ATTENTION`인 Job은 다음 시작 요청에서 `RUNNING_TASKS`로 재개한다.
- JSON/schema 해석, 참조 ID 경계, 입력 hash, 경로 보안, write-once 파일 digest처럼 손상 또는
  잘못된 게시를 막는 무결성 검사는 유지한다.
- 품질은 프롬프트 개선, 선제 shard, 관찰 지표 추세, 고정 평가 corpus와 shadow run을 통해
  점진적으로 개선한다. 개별 문서 Job은 평가 점수 때문에 중단하지 않는다.

## 결과

문서가 부분적으로 불완전할 수 있는 대신 장시간 실행이 품질 휴리스틱 때문에 소실되지 않는다.
사용자는 항상 생성 결과를 검토할 수 있고, 팀은 동일 지표의 버전별 추세로 모델·프롬프트 개선을
판단한다. 데이터가 비었거나 손상되어 안전하게 읽고 재개할 수 없는 경우에는 계속 실패 처리한다.
